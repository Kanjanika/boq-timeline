⚙️ จัดการ Step Template

กำหนดจำนวน Stage · ชื่อ Stage · สัดส่วนเวลาของแต่ละ Service Type · Blank BOQ กับ Pretender เป็นงานคนละข้อกัน (Blank BOQ = S1–S4, Pretender = S5–S8 ต่อเนื่องกันตามธรรมเนียมเดิม) — ตัวอื่นเป็นค่าเริ่มต้นคร่าวๆ ให้มาปรับ

🗄️ Backfill ข้อมูลจริงทั้งหมดลง BOQ Step Tracking

สร้าง Step จริงใน SharePoint ให้ครบทุกแถวที่ยังเป็น "⚠ ประมาณการ" (คำนวณจาก Start/Finish Date ของ BOQ Team Work Plan เฉยๆ ยังไม่มี Step จริง) หลังจากนี้ข้อมูลจะกลายเป็นของจริงที่แก้ไข/บันทึก progress รายวันได้ตรงๆ ไม่ใช่ค่าประมาณการอีกต่อไป

🗑️ ลบ Step Tracking ซ้ำซ้อนของ AIES · ST

บั๊กที่แก้ไปแล้วใน build 2026-08-17.8 ทำให้ระบบสร้าง Step Tracking ของ AIES (SubTeam: ST) ซ้ำทับกันหลายชุด (ทุกครั้งที่บันทึกผู้ทำ ระบบเข้าใจผิดว่ายังไม่มี Step จริง เลยสร้างใหม่ทับซ้ำ) ปุ่มนี้จะลบทุกรายการ BOQ Step Tracking ที่ Project=AIES และ SubTeam=ST ทิ้งทั้งหมด เพื่อกรอกผู้ทำ S1-S4 ใหม่ให้สะอาดอีกครั้ง (ตอนนี้จะติดจริงไม่ซ้ำอีกแล้ว) — ลบแล้วกู้คืนไม่ได้

🔍 ตรวจสอบชื่อโครงการไม่ตรงกัน

เช็คว่าชื่อโครงการใน "BOQ Step Tracking" (Project field) กับ "BOQ Team Work Plan" (Title) ตรงกันทุกโครงการไหม — ถ้าไม่ตรงกัน (เช่น "Hilton" vs "Hilton Krabi") ระบบจะหาโครงการนั้นใน Team Work Plan ไม่เจอ ทำให้ต่อให้ตั้ง Status เป็น "Done" แล้ว ก็ยังไม่ถูกซ่อนออกจาก Timeline เพราะเทียบชื่อกันไม่ติด

🌱 Seed ข้อมูล Procurement Plan Reference

สร้างแถวอ้างอิงระยะเวลา Blank BOQ/Pretender ให้ครบตามตาราง "Procurement Plan Schedule Rev.1" (18 ส.ค. 2568) — 6 ประเภทอาคาร × 3 ขนาด GFA × 4 Package × 2 Service Type = 144 แถว ระบบจะข้ามแถวที่มี Title ตรงกับที่มีอยู่แล้วใน SharePoint (กันสร้างซ้ำถ้ากดปุ่มนี้มากกว่า 1 ครั้ง) HistMultiplier ตั้งต้นที่ 1.0 ทุกแถว (ทีมปรับเองได้ทีหลังจากข้อมูลจริง ผ่านการแก้ไขตรงๆ ใน SharePoint)

🔧 เพิ่ม Choice ใหม่ตาม PDF4 ให้ Service Type

เพิ่มตัวเลือกละเอียดของ Budget/VO/Cost Exercise/VE ตามเอกสาร "Turnaround Time Framework" (9 ก.พ. 2569) เข้าไปในฟิลด์ "Service Type" ของ BOQ Team Work Plan — ไม่ลบ/แก้ตัวเลือกเดิมที่มีอยู่แล้ว (งานเก่า 334 รายการที่ยังเป็นหมวดกว้าง เช่น "Budget" เฉยๆ จะไม่กระทบ) ทีม Post ต้องเริ่มเลือกตัวเลือกละเอียดพวกนี้แทนตอนสร้างงานใหม่ ถึงจะคำนวณระยะเวลาตามขนาดโครงการได้แม่นตาม PDF4

🔍 ตรวจสอบ Column ใน BOQ Step Tracking

เช็คว่าคอลัมน์ StepAssignee เป็นชนิด "Person or Group" หรือข้อความปกติ — ถ้าเป็น Person or Group การ sync ชื่อแบบข้อความธรรมดาจากแอปนี้จะไม่ถูกบันทึก (เห็นเป็นช่องว่างใน SharePoint แม้ RoleInStep/StepNotes จะบันทึกได้ปกติ)

🔍 ตรวจสอบ Procurement Plan Reference

เช็คว่า list นี้มีคอลัมน์ GFA/ประเภทอาคาร/Package อยู่แล้วหรือยัง (สำหรับคำนวณระยะเวลาให้แปรผันตามขนาดโครงการตามเอกสาร Procurement Plan Schedule / Turnaround Time Framework) พร้อมโชว์ตัวอย่างข้อมูลจริงในนี้ตอนนี้ให้ดู

🔎 ค้นหา SharePoint User ID

สแกนฟิลด์ "ผู้สร้าง/ผู้แก้ไขล่าสุด" (Author/Editor) ของทุกรายการใน BOQ Team Work Plan และ BOQ Step Tracking เพื่อดึง User ID (ตัวเลข) ของแต่ละคนที่เคยสร้าง/แก้ไขรายการ — ใช้เติมใน USER_ID_MAP ของโค้ดเพื่อให้ sync StepAssignee (Person field) กลับ SharePoint ได้ ผลลัพธ์จะครบเฉพาะคนที่เคยสร้าง/แก้ไขรายการใน 2 list นี้มาก่อนเท่านั้น

📇 กรอก User ID Map

กรอก SharePoint User ID (ตัวเลข) ของแต่ละคน เพื่อให้ระบบ sync ผู้ทำ (StepAssignee) กลับ SharePoint ได้ถูกต้อง (Person or Group field ต้องใช้ ID ตัวเลข ไม่ใช่ชื่อข้อความ) — เว้นว่างไว้ได้ถ้ายังไม่รู้ ID ของคนนั้น บันทึกแล้วมีผลทันทีโดยไม่ต้องแก้โค้ด/deploy ใหม่ (เก็บไว้ในเบราว์เซอร์นี้)
